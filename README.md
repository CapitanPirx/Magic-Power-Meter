# Magic Power Meter

Программа для замера энергопотребления мобильного устройства с помощью ардуино. По сути просто удобная софтина для работы с ардуино под конкретную задачу. Это нативное приложение для macOS 14+ на SwiftUI и Swift Charts для измерений с помощью Arduino и INA219. Интерфейс на русском языке, синие и бирюзовые акценты соответствуют значку приложения. Откройте `MagicPowerMeter.xcodeproj` и запустите схему `MagicPowerMeter` на My Mac.

Кнопка темы в закреплённой верхней панели, над блоком подключения, переключает светлое и тёмное оформление всего интерфейса, включая настройки порта и предупреждения. При каждом запуске включается тёмная тема; выбор хранится только в памяти и не влияет на измерения.

## Измерения

1. Закройте CoolTerm и другие клиенты последовательного порта. Откройте настройки порта, выберите реальный датчик или явно обозначенный демонстрационный источник и подключитесь.
2. Значения по умолчанию: скорость 9600 бод, 8N1, без управления потоком, LF/CRLF, тайм-аут 8 секунд для получения корректных данных. Протокол: `count;voltage_V;current_mA;power_W`; дробная часть может отделяться запятой или точкой. При автоматическом выборе приложение проверяет каждый порт, пока не получит корректное показание датчика. Подключение и подготовка могут перезапустить Arduino, но не запускают измерение.
3. Выберите одиночный режим, режим сравнения или спринт, а также общую длительность (по умолчанию 180 секунд). В режиме сравнения можно редактировать названия условий и задавать число итераций для каждого из них. Спринт использует фиксированный независимый шаблон 5×3: ВДНХ статика (авторизован), ВДНХ статика (неавторизован), ВДНХ динамика (авторизован), ВДНХ динамика (неавторизован), Сочи Дендрарий динамика. Создайте сессию; чтобы изменить её название, нажмите «Переименовать» рядом с заголовком. Пустые имена и имена только из пробельных символов не принимаются. Названия и режимы сохраняются в истории в памяти; переименование не меняет идентификаторы сессий или имена экспортируемых файлов.
4. Выберите итерацию, вручную подготовьте сценарий на телефоне и нажмите Start. После завершения итерации кнопка Start выберет следующую незавершённую ячейку по порядку плана и запустит её одним нажатием. Приоритет имеет явно выбранная незавершённая ячейка. Запись не переходит к следующей итерации без нажатия Start; когда все ячейки завершены, кнопка Start отключается. Длительность прошедшего, оставшегося и запланированного времени отображается в формате `m:ss` (например, `0:09`, `3:00`). Монотонный таймер останавливается по достижении заданной длительности. Кнопка Stop прерывает попытку: она остаётся в сырых логах, но не участвует в расчётах результатов.
   В режимах сравнения и спринта выберите записанную ячейку и нажмите «Перезамер», чтобы повторить измерение. Предыдущий полный результат продолжает учитываться, пока не завершится новая полная попытка; только после этого новый результат заменяет его в средних значениях, прогрессе, таблицах, графиках и CSV. Прерванная, превысившая тайм-аут или неудачная замена сохраняет предыдущий результат. Все прежние попытки и точные исходные байты доступны через кнопки попыток; для каждой явно указано, участвует ли она в расчётах.
5. Завершите сессию, чтобы открыть вкладки «Таблица» и «Графики» и сформировать CSV в памяти. На вкладке графиков можно выбрать любой сценарий или итерацию, в том числе незавершённые и ещё не записанные ячейки (они помечены соответствующим образом); используются исходные шкалы 0–15 W и времени сессии. Для досрочного завершения требуется подтверждение, а результат помечается как неполный.
   Повторное измерение доступно и после завершения сессии: при остановке попытки сессия возвращается в завершённое состояние, а таблица, графики и CSV в памяти обновляются. Если выбрана папка, автоматический экспорт использует обновлённый снимок данных. При создании новой сессии завершённые сессии остаются доступными в памяти. В одиночном режиме отдельного действия для повторного измерения нет.

Для графика всегда используется диапазон 0–15 W; значения за его пределами сохраняются в данных и учитываются при расчёте среднего. Приложение сообщает о некорректных строках, пропусках счётчика, сбросах и временных пропусках. Пустые запуски и запуски с недостаточным покрытием начала или конца либо с пропусками, превышающими тайм-аут, нельзя завершить. Короткий пропуск или некорректная строка считаются предупреждением: данные не интерполируются и не заменяются нулевыми отсчётами.

Прошедшее время измеряется непрерывными монотонными часами, в том числе во время сна системы; фактические настенные временные метки и время обнаружения задержанной остановки записываются отдельно. Во время записи отключается переход системы в режим сна из-за бездействия. Если команда ручной остановки поступает после дедлайна, приложение сохраняет завершённое измерительное окно.

## Экспорт и конфиденциальность

Выберите папку с помощью системного окна выбора папки. Данные остаются в памяти, пока не будет подтверждена успешная запись. Флажок сырых логов сохраняет все попытки после остановки; при завершении сессии CSV автоматически сохраняется, если выбрана папка. Кнопки экспорта позволяют повторить запись. Без экспорта данные не сохраняются после перезапуска приложения.

CSV использует BOM UTF-8, разделители-точки с запятой, запятые в качестве десятичных разделителей, названия условий в кавычках и пустые ячейки для отсутствующих значений. В режиме сравнения дельта для каждой итерации рассчитывается относительно соответствующей базовой итерации. В последней строке отдельно усредняются средние значения завершённых итераций для каждого условия; дельты рассчитываются по этим средним, а не по усреднённым процентам. Если базовое значение равно нулю, процент не рассчитывается. Полнота и источник повторяются в каждой строке CSV, поэтому метки неполных и демонстрационных результатов не теряются.

Интерфейс и CSV спринта содержат независимые средние значения сценариев без базового условия и столбцов дельты.

Файлы `.txt` содержат точные полученные байты, а не пересозданный CSV. Связанный файл JSON указывает источник, условие, итерацию, попытку, участие в расчётах, подключение, временные метки, смещения байтов фрагментов исходных данных и диагностику. Имена демонстрационных файлов начинаются с `DEMO-`. Поле `complete` описывает полноту попытки; поле `included_in_calculations` имеет значение true только для текущего успешного результата ячейки, но не для заменённых полных попыток.

Приложение работает в песочнице с разрешениями на доступ к последовательному устройству и запись в выбранную пользователем папку; у него нет сетевых возможностей и внешних зависимостей.

## Разработка

```sh
swift test
swiftc -parse-as-library MagicPowerMeter/Core/*.swift MagicPowerMeter/SerialTransport.swift \
  IntegrationTests/DesktopSmoke.swift -o .build/desktop-smoke
.build/desktop-smoke
swiftc -parse-as-library MagicPowerMeter/Core/*.swift MagicPowerMeter/MeterAppearance.swift \
  MagicPowerMeter/ContentView.swift IntegrationTests/AppearanceSmoke.swift -o .build/appearance-smoke
.build/appearance-smoke
xcodebuild -project MagicPowerMeter.xcodeproj -scheme MagicPowerMeter \
  -configuration Debug -destination 'platform=macOS' -derivedDataPath build \
  CODE_SIGN_IDENTITY=- build
```

Основные тесты запускаются отдельно от интерфейса с помощью Swift Package Manager. Интеграционный smoke-тест настольной версии использует псевдотерминал POSIX и явно выбранный демонстрационный источник (датчик не открывается). Smoke-тест оформления проверяет действие привязки кнопки темы SwiftUI, контрастность и рабочий форматтер длительности, включая некорректные и большие значения.

При желании передайте пути к папке для результатов и собранному `.app`, чтобы сохранить собственные встроенные SwiftUI-превью приложения в обеих темах (подготовка, следующий запуск Start, запись, вкладки результатов, переименование, повторное измерение, спринт и настройки порта) без записи экрана. Процесс превью загружает скомпилированный значок из этого пакета, а не значок исполняемого файла командной строки.

Для каждого сохранённого представления также проверяется унифицированный журнал его процесса на несовпадения аргументов форматирования Foundation; такие диагностики ненадёжно отображаются в stderr. Средние значения рассчитываются потоково, без промежуточных массивов и кэшированной статистики, с сохранением исходного порядка инкрементальных вычислений. При записи сырых логов форматтер даты используется повторно в рамках одного экспорта, но не между параллельными экспортами. Регрессионные тесты фиксируют результаты с плавающей точкой, включение итераций и точные байты метаданных CSV и сырых логов.

Пользовательские русскоязычные строки находятся в `MagicPowerMeter/Core/Strings.swift`: это типизированные константы и функции с параметрами, а не ключи локализации. Маркеры протокола, ключи JSON, пути и идентификаторы SF Symbol остаются рядом с использующим их кодом. Ожидаемые значения тестов заданы независимыми литералами. SwiftPM и синхронизированная группа исходников Xcode автоматически включают этот файл.

`Core/MeterModel.swift` отвечает за процесс измерения и наблюдаемое состояние интерфейса; он использует `SensorTransport` и `MeasurementExporting`, а не конкретные реализации последовательного порта или файлового экспорта. `SerialTransport` отвечает за работу с POSIX/IOKit; `FileMeasurementExporter` сериализует неизменяемые запросы сессии и папки и передаёт исходные ошибки. `ExportFolder` отвечает за выбор папки и доступ с ограниченной областью действия. `MyApp.swift` связывает производственные службы и системный выбор папки. Ядро не зависит от AppKit/SwiftUI; тесты модели используют подменные службы для проверки поколений подключения, отложенного экспорта, снимков данных, повторных попыток и отмены.

Для проверки оборудования требуется реальное устройство Arduino/INA219; проверка на демонстрационном источнике не подтверждает совместимость с оборудованием. Автоматические сценарии на iPhone, XCUITest и оркестрация CI не входят в текущий MVP.
